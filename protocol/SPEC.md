# RAVEN Protocol V1 — Specification Index

**Version:** 1 (`rvn1`)
**Status:** Wire codec frozen; **production security hold**. Read
[`SECURITY_ERRATA_RVN1_2026-08-13.md`](SECURITY_ERRATA_RVN1_2026-08-13.md)
before implementing or deploying RVN1. The errata overrides conflicting
processing and release claims below. Every normative wire claim in this family is backed by a
committed reference implementation (`protocol/reference/raven_protocol/`) and a
deterministic vector tree (`shared-vectors/rvn1/`, generated by
`protocol/reference/generate_rvn1.py`). A wire-format change requires a new version
byte and a new vector tree — see [Versioning policy](#versioning-policy) below.
**Version inventory:** frozen vs draft families, RDAP, negotiation drift, and
CI consumer honesty (including .NET **NOT YET** and iOS/Watch jobs blocked on
this serverless `main`) are listed in
[`PROTOCOL_VERSIONS.md`](PROTOCOL_VERSIONS.md).
**Audience:** anyone re-implementing RAVEN V1 in another language (Rust node —
Phase B; Swift/C#/Kotlin ports; any future client).

This index does not restate the product mission. It states what the wire protocol
guarantees and where to find the byte-exact proof of each guarantee.

## The seven V1 invariants

Every sub-spec below exists to make one of these true, and every negative vector
exists to prove a violation of one of these is rejected.

1. **Identity.** Every participant is a self-sovereign Ed25519 identity keypair
   generated and held on-device. No server issues it, stores it, or can revoke it.
   See [`RAVEN_IDENTITY_V1.md`](RAVEN_IDENTITY_V1.md).
2. **Text.** Message content is never carried in the clear on any transport. The
   wire envelope carries opaque ciphertext and routing metadata only — no
   plaintext identities, usernames, or conversation IDs. See
   [`RAVEN_ENVELOPE_V1.md`](RAVEN_ENVELOPE_V1.md).
3. **Delivery.** The delivery-state machine advances to "delivered" or "read"
   only on a signed, recipient-issued acknowledgment. A transport accepting or
   relaying a frame is never sufficient on its own. See
   [`RAVEN_ACK_V1.md`](RAVEN_ACK_V1.md).
4. **Offline delivery.** An envelope addressed to an offline recipient stays
   valid and deliverable via store-and-forward relays with no online path to the
   recipient and no central queue. Routing does not require a live connection to
   the recipient at send time. See [`RAVEN_ENVELOPE_V1.md`](RAVEN_ENVELOPE_V1.md)
   (hop/replication fields) and [`RAVEN_ROUTING_TAG_V1.md`](RAVEN_ROUTING_TAG_V1.md).
5. **Internet.** Over an internet transport (e.g. a libp2p/DHT bridge), the
   object exchanged is the exact same `RavenEnvelopeV1` byte stream used
   everywhere else — no server-side reformatting, no protocol translation.
6. **Bluetooth.** Over BLE mesh, the object is the same `RavenEnvelopeV1` byte
   stream, fragmented for MTU but not transcoded. A relay forwards bytes; it
   does not decrypt or re-author them.
7. **Security target (production held).** Only an authenticated intended
   endpoint may recover plaintext. RVN1 currently excludes
   `dest_device_hint`, `hop_limit`, and `replication_budget` from the sender
   signature; this permits cooperative relaying but also lets a Byzantine
   relay raise those values. They are therefore policy hints, not an
   authenticated forwarding bound. See
   [`SECURITY_ERRATA_RVN1_2026-08-13.md`](SECURITY_ERRATA_RVN1_2026-08-13.md)
   before relying on this invariant.

## The four mission invariants

These are the product-level constraints the seven protocol invariants above
exist to serve. Stated tersely — see the roadmap docs for the full mission, not
this file.

- **No trusted central server.** Discovery, routing, and delivery all function
  with no operator who can read, block, or must be trusted with plaintext.
- **Only the intended endpoint recovers plaintext.** Not a relay, not a bridge,
  not the app vendor.
- **Same protocol object across Internet / relay / BLE.** One wire format, one
  envelope, everywhere — see invariants 5 and 6 above.
- **`ash` makes the network usable** without the user needing to understand
  DHT, QUIC, Noise, ratchets, NAT traversal, or routing tags. Everything in
  this document family is what `ash` hides.

## Versioning policy

- Every wire format defined in this family carries an explicit version field:
  the `version` byte in `RavenEnvelopeV1` (`RAVEN_ENVELOPE_V1.md`), the
  `protocol_version` string in every vector fixture, and the implicit version
  carried by each record type's domain-separation prefix (`"rvn1/ack"`,
  `"rvn1/alias"`, `"rvn1/devcert"`, `"rvn1/caps"`, `"rvn1/route"`).
- A receiver that sees a **higher** version than it supports MUST drop the
  object (silently, or surface "update required" at the application layer). It
  MUST NOT attempt to parse a higher-versioned object using its own layout —
  a version bump is licensed to change the byte layout entirely.
- A **lower** version than currently shipped MAY be supported for
  backward-compatibility at an implementation's discretion; this document
  family does not mandate how long `v1` must be accepted once `v2` exists.
- Capability negotiation is separate from and layered on top of version
  negotiation: capabilities are **negotiated and signed** (see
  `RAVEN_CAPABILITIES_V1.md`), so a peer's advertised optional-feature set
  cannot be silently downgraded by an on-path relay the way an unsigned
  capability advertisement can.
- A wire-format change that breaks byte-for-byte compatibility with any vector
  in `shared-vectors/rvn1/` is a `v2` change: it gets a new vector tree
  (`shared-vectors/rvn2/`), not an edit to this one. `shared-vectors/rvn1/` is
  frozen once this document family is committed.
- Inventory of frozen families (`v1` mesh BLE, `rvn1`), draft/production-disabled
  companions, and which **Raven Serverless Node** jobs can be cited on this
  tree: [`PROTOCOL_VERSIONS.md`](PROTOCOL_VERSIONS.md).

## Reference implementation

- Python reference codec + signer for every record type in this family:
  `protocol/reference/raven_protocol/` (`address.py`, `fingerprint.py`,
  `envelope.py`, `ack.py`, `alias.py`, `device_cert.py`, `routing_tag.py`,
  `bech32m.py`, `_canon.py`).
- Deterministic vector generator: `protocol/reference/generate_rvn1.py`
  (fixed RFC-8032 test keys, fixed epoch `1700000000`, fixed `K_route`).
- Test suite exercising the reference codec against the vectors:
  `protocol/reference/tests/`.
- Legacy/shipping mesh transport this family supersedes for the wire format
  (BLE GATT layer, chunking, legacy JSON envelope schemas): see
  [`../docs/MESH_PROTOCOL.md`](../docs/MESH_PROTOCOL.md). That document remains
  the source of truth for the BLE transport layer (GATT UUIDs, MTU chunking,
  advertisement payload) — this family only redefines the envelope carried
  *inside* that transport (and inside the internet-bridge transport, and any
  future transport).
